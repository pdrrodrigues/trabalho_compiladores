# Static LALR(1) table audit

The parser uses a dense `int16_t action[152][71]` table. Columns 0-48 are
terminals and columns 49-70 are nonterminals/GOTO symbols. Zero means error,
a positive value is a shift or GOTO state, a negative value is a reduction by
the corresponding positive production number, and 32767 means accept. The
secondary `uint16_t production[70][2]` table stores RHS length and LHS symbol.

The state inventory below records the complete independently reviewable
derivation. Canonical LR(1) states: 469; LALR(1) states after merging identical
LR(0) kernels: 152. The PDF grammar has one dangling-`else` shift/reduce
conflict, in state 131 on `ELSE`; the table chooses shift so `else` binds to
the nearest eligible `if`. There are no other shift/reduce conflicts and no
reduce/reduce conflicts.

The checked-in arrays in `syntax_analyzer/src/parser_tables.inc` are the runtime
source of truth. They are deliberately static: building or running the analyzer
does not invoke a parser generator.
